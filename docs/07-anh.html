Kết luận

Ảnh FlashTrend tự tạo (biểu đồ run, ảnh bìa) được POST multipart tới image host bên thứ ba (lệnh mẫu bên dưới); Supabase chỉ lưu URL trả về cùng sha256 trong bảng media. Thumbnail YouTube đã có URL công khai (i.ytimg.com) nên không cần upload, chỉ lưu vào videos.thumbnail_url.

  1. Không dùng Supabase Storage: gói Free chỉ có 1 GB storage và 5 GB egress cho cả hai repo.1
  2. sha256 là khoá duy nhất: một ảnh chỉ upload một lần, kể cả khi run chạy lại.
  3. Endpoint là API nội bộ của một website, không phải dịch vụ ảnh có hợp đồng: phải coi là có thể hỏng bất cứ lúc nào.
  4. estfstudio cũng upload ảnh bìa từng phần lên cùng host, theo đúng quy trình dưới đây (owner = 'estfstudio', kind = 'cover').

Một ảnh đi qua những bước nào?

Cấu trúc sơ đồ
  • GitHub Actions job job
  • Supabase db
  • Image host host
  • estfstudio estf
  • job → db · sha256 đã có trong media?
  • db → job · không có
  • job → host · POST /files/upload (multipart)
  • host → job · JSON chứa URL
  • job → db · insert media (url, sha256, bytes)
  • estf → db · đọc digest + image_url
  • db → estf · top 10 ý tưởng
  1. GitHub Actions job ↗

    Tính sha256 của tệp; nếu đã có trong media thì dùng lại URL, bỏ qua upload.

  2. Image host ↗

    Gửi file=@<ảnh>;type=image/png, giới hạn 2 MB, timeout 30 giây, thử lại 2 lần.

  3. Supabase ↗

    Lưu url, host, sha256, bytes, kind, video_id hoặc run_id.

  4. estfstudio ↗

    Lấy image_url từ view digest, gửi ảnh qua Telegram bằng URL (không tải về).

Phía estfstudio dùng adapter riêng infrastructure/image_host.py bằng urllib (dự án không thêm requests); upload lỗi không chặn việc đăng bài, chỉ để cover_media_id trống. Cron HEAD url hằng tuần của FlashTrend kiểm mọi hàng media, kể cả owner = 'estfstudio'.
