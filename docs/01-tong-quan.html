Kết luận

FlashTrend là bộ lọc thống kê–ngữ nghĩa chạy 1–2 lần/ngày trên GitHub Actions: lấy video YouTube, giữ video vượt trội so với chính kênh của nó, gộp ý tưởng trùng, nhờ Gemini viết góc làm lại, rồi ghi vào Supabase để estfstudio đọc.

  1. Không reup, không tải video ở MVP: chỉ đọc metadata qua API chính thức.1
  2. Supabase là nguồn sự thật duy nhất; JSON/PNG trên Actions chỉ để debug.1
  3. Repo này không có Telegram: bot của estfstudio đọc thẳng cùng project Supabase.
  4. Ảnh tự tạo (biểu đồ run, ảnh bìa) được upload qua một image host bên thứ ba; Supabase chỉ giữ link. Thumbnail YouTube dùng thẳng link i.ytimg.com, không upload.

Bài toán và câu hỏi nghiên cứu

Người làm nội dung không thiếu video, mà thiếu tín hiệu sớm: video nào thật sự đột biến, ý tưởng nào không trùng, và góc làm lại nào đủ khác để không dính Content ID hay reused content.

Câu hỏi nghiên cứu: kết hợp API chính thức, trình trích metadata, toán (thống kê, đại số tuyến tính, giải tích, đồ thị) và Gemini thế nào để mỗi ngày ghi vào Supabase một tập ý tưởng độc đáo và có xác suất viral cao, cho estfstudio đọc và gửi Telegram?

Những thành phần nào nói chuyện với nhau?

Cấu trúc sơ đồ

  • YouTube Data API yt
  • Gemini API gem
  • Image host img
  • Supabase Postgres db
  • estfstudio (Telegram) estf
  • cron → yt · metadata
  • cron → gem · 3–5 ý tưởng
  • cron → img · PNG
  • cron → db · runs, ideas
  • estf → db · đọc digest

GitHub Actions là nơi duy nhất gọi API bên ngoài. estfstudio chỉ đọc và ghi trạng thái vào Supabase, không gọi YouTube hay Gemini của FlashTrend.

  1. GitHub Actions cron ↗

    Chạy lúc 07:17 giờ Việt Nam hằng ngày (cron 17 0 * * *: GitHub chỉ nhận cron theo UTC, 00:17 UTC = 07:17 giờ VN), có workflow_dispatch để chạy tay; timeout 10 phút.

  2. YouTube Data API ↗

    Chart mostPopular theo region + search.list theo từ khoá + baseline kênh. Chỉ cần API key.

  3. Gemini API ↗

    Chỉ đọc 3–5 ý tưởng đã lọc; trả JSON summary, hook, angles[3], risk.

  4. Image host ↗

    Upload biểu đồ của run, nhận URL công khai, ghi vào bảng media.

  5. Supabase Postgres ↗

    Postgres + pgvector, gói Free; RLS bật, không có policy cho anon.

  6. estfstudio bot ↗

    Đọc run ok mới nhất, gửi Telegram, ghi ideas.status và feedback.

Một lần chạy đi qua những lớp nào?

Cấu trúc sơ đồ
  • Lấy video + kênh collect
  • L1 Z-Score l1
  • L2 Cosine dedup l2
  • L3 Gemini l3
  • Ghi Supabase store
  • collect → l1
  • l1 → l2 · outlier
  • l2 → l3 · leader
  • l3 → store · llm

Lớp rẻ chạy trước: Z-Score là O(n) và cắt phần lớn nhiễu trước khi phải mã hoá văn bản thành vector.

  1. Lấy video + kênh ↗

    A1 chart, A2 từ khoá, A3 channel_avg_views (cache 24 h trong bảng channels).

  2. L1 Z-Score ↗

    performance_ratio, engagement Bayes, time-decay; giữ z_score >= 1.5.

  3. L2 Cosine dedup ↗

    Embedding MiniLM 384 chiều; cosine ≥ 0.70 thì chung cụm, giữ video điểm cao nhất.

  4. L3 Gemini ↗

    Viết tóm tắt, hook, 3 góc mới, rủi ro bản quyền vào ideas.llm.

  5. Ghi Supabase ↗

    runs.status = ok chỉ khi mọi idea có llm đủ schema; lỗi thì error.

Sau năm lớp của MVP còn hai lớp tuỳ chọn: L4 (v2) lấy nguồn → biến đổi → hẹn lịch YouTube, và L5 đồ thị độ trung tâm hashtag sau khi có đủ dữ liệu. Hai lớp đầu đi trước vì Z-Score O(n) cắt 80–90 % nhiễu trước bước mã hoá văn bản đắt hơn, hợp với CPU của Actions.

Vì sao repo public?

Repo public được dùng phút Linux của Actions không giới hạn; private chỉ có 2.000 phút/tháng.2 Secrets nằm trong GitHub Secrets nên public không làm lộ khoá, miễn là không hardcode.
