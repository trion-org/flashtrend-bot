Kết luận

Bốn secret là đủ cho MVP (thêm S3_URL nếu muốn có ảnh biểu đồ): SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, YOUTUBE_API_KEY, GEMINI_API_KEY. Làm theo thứ tự GitHub → Supabase → YouTube → Gemini → Actions; OAuth upload và cookie yt-dlp chỉ cần ở v2.

  1. Không có TELEGRAM_* trong repo này: token bot thuộc estfstudio.1
  2. Dùng service_role, không dùng anon: RLS bật và không có policy, nên anon không ghi được.
  3. API key YouTube chỉ giới hạn theo API, không giới hạn IP: IP của GitHub Actions thay đổi liên tục.
  4. Image host (trang 07) không cần khoá, chỉ cần địa chỉ upload trong secret S3_URL (tuỳ chọn; thiếu thì bỏ qua ảnh biểu đồ).

Google Cloud và Gemini

  1. Project + bật API

    console.cloud.google.com, cùng tài khoản sở hữu kênh (v2 cần) → New Project flashtrend-bot → APIs & Services → Library → YouTube Data API v3 → Enable.

  2. API key

    Credentials → Create credentials → API key → YOUTUBE_API_KEY (dạng AIzaSy…).

  3. Siết key

    Edit API key → API restrictions → Restrict key → chỉ YouTube Data API v3; Application restrictions để None (IP của Actions đổi liên tục, giới hạn IP sẽ 403).

  4. Gemini key

    aistudio.google.com/apikey → Create API key, nên gắn vào cùng project flashtrend-bot để gom quota; nếu có mục restrict thì chỉ cho Generative Language API.

  5. Model

    Mặc định gemini-2.5-flash (rẻ, đủ JSON có cấu trúc); kiểm danh sách model trên AI Studio khi code, đổi nếu bị deprecate.

5

Workflow chạy theo lịch

GitHub luôn đọc cron theo UTC.2 Phút lệch 17 tránh hàng chờ đầu giờ; cron theo giờ có thể trễ vài phút khi GitHub bận. Việc nặng không chạy mỗi giờ mà theo app_config và giờ Việt Nam: tìm từ khoá YouTube mỗi youtube_search_every_hours giờ (6 → 00, 06, 12, 18h), vẽ và upload biểu đồ mỗi analysis_every_hours giờ (3). Runner Ubuntu không có font Hán, nên workflow cài fonts-noto-cjk khi thiếu; không có font thì chữ Hán bị bỏ khỏi nhãn biểu đồ. Bản đầy đủ nên có thêm bước python -m pip install --upgrade pip và restore-keys: ${{ runner.os }}-pip- cho cache.

Chạy một lần theo yêu cầu. workflow_dispatch nhận thêm ba input: mode (digest · trending · search, xem mục "Ba chế độ chạy" của trang bảng mở rộng), query (từ khoá của chế độ search) và request (mã yêu cầu, lưu vào runs.request_id). Từ khoá là chữ người dùng gõ nên đi vào chương trình qua biến môi trường và được đặt trong ngoặc kép (--query "$FT_QUERY"), không bao giờ ghép thẳng vào script. run-name mang chế độ và mã yêu cầu; concurrency tách theo mã yêu cầu để lần tìm chạy song song với lần chạy mỗi giờ.

Chạy thử: tab Actions → workflow FlashTrend digest → Run workflow. Log không được in YOUTUBE_API_KEY, SERVICE_ROLE, GEMINI_API_KEY (GitHub chỉ che khi trùng chuỗi chính xác). Nếu cài torch thì chỉ bản CPU: pip install torch --index-url https://download.pytorch.org/whl/cpu.

6

Supabase: tạo project và chạy schema

  1. Tạo project

    supabase.com → New project; tên flashtrend-bot; region Singapore (gần Việt Nam nhất); gói Free; lưu mật khẩu DB vào trình quản lý mật khẩu.

  2. Lấy URL và key

    Project Settings → API: Project URL → SUPABASE_URL; service_role → Reveal → SUPABASE_SERVICE_ROLE_KEY (JWT bắt đầu eyJ).

  3. Chạy DDL

    SQL Editor → New query → chạy lần lượt sql/01_core.sql, 02_media.sql, 03_functions.sql; create extension if not exists vector nằm đầu 01.

  4. Migration 07

    sql/07_analysis.sql chạy trên mọi database, mới hay cũ: thêm loại ảnh analysis, cột caption/position, bảng hot_videos và các cột chu kỳ. Chạy lại không hại.

  5. Seed app_config

    sql/04_seed_app_config.sql (chạy lại được, cập nhật hàng tại chỗ). Thứ tự trên database đã có từ trước: 05_search_tuning.sql, 06_bilibili.sql, 07_analysis.sql, rồi 03_functions.sql (hàm dọn dẹp mới) và 04 cuối cùng; chúng chỉ thêm cột/bảng, chạy lại không hại.

  6. Chung với estfstudio

    Một project cho cả hai repo; thứ tự: DDL lõi, bảng media, rồi estfstudio chạy migration estf_* (mốc m1 trong kế hoạch của nó).

Connection string (chỉ khi sau này dùng psycopg): Project Settings → Database → URI chế độ Transaction pooler, cổng 6543; lưu thành secret SUPABASE_DB_URL, không commit.

Host và region đổi theo project. MVP chỉ cần supabase-py + URL + service_role. Mật khẩu DB chỉ cần cho connection string, không đưa lên GitHub. Khoá anon / publishable bị RLS chặn nên job không ghi được; service_role bỏ qua RLS — coi như root: chỉ để trong Secret, không log, không đưa vào client.

7

v2: OAuth để upload YouTube

Chỉ cần khi đăng video bạn có quyền. App chưa qua OAuth Verification thì video bị khoá Private.

  1. OAuth consent screen

    Cùng project Google Cloud → User Type External → tên app FlashTrend Bot, email hỗ trợ và liên hệ developer → scope https://www.googleapis.com/auth/youtube.upload → Test users: Gmail sở hữu kênh.

  2. OAuth client

    Credentials → OAuth client ID → Desktop app (script) hoặc Web application với redirect https://developers.google.com/oauthplayground → lấy Client ID (…apps.googleusercontent.com) và Client Secret (GOCSPX-…).

  3. Refresh token

    OAuth 2.0 Playground → bánh răng → Use your own OAuth credentials → chọn scope youtube.upload → Authorize bằng test user → Exchange → Refresh token (1//0g…).

  4. Lưu secret

    YOUTUBE_CLIENT_ID, YOUTUBE_CLIENT_SECRET, YOUTUBE_REFRESH_TOKEN; access token sống ~1 giờ, script tự xin lại bằng refresh token.

  5. Production

    Gửi OAuth Verification trước khi kỳ vọng publishAt tự công khai video.

8

Cookie Bilibili: flashtrend-bot không cần

flashtrend-bot chỉ tìm kiếm và tìm Bilibili ẩn danh (trang 04), nên không có secret BILI_COOKIES. Cookie đăng nhập chỉ cần khi tải video chất lượng cao, và việc tải thuộc estfstudio: nó đọc .secrets/cookies.txt ở máy bạn, đưa cho yt-dlp một bản sao chỉ chứa cookie Bilibili, và cảnh báo khi phiên sắp hết hạn (tài liệu estfstudio v1.1.0, trang 02).

  • Cookie là thông tin đăng nhập: không bao giờ commit cookies.txt, không đặt vào GitHub Secrets của repo công khai này.
  • Cookie xuất từ trình duyệt sống khoảng một ngày; không dùng cookie của người khác.
